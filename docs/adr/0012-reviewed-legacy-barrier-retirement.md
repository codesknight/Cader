# ADR 0012：用户审定旧缺参屏障，保留未知原记录

日期：2026-11-21；状态：实施；关联 [#20](https://github.com/codesknight/Cader/issues/20)、[#19](https://github.com/codesknight/Cader/issues/19)。

## 背景

dev.3阻止缺参请求发送，但用户升级后仍被dev.2留下的Drawing6 dispatch/unknown屏障阻断。重启不能证明旧请求未执行，原连接消失也无法做同连接postflight恢复。原设计缺少可审计的人工审定入口；自动按远端报错文字放行不成立。

## 决定

- 启动读取持久屏障并明确告知。已知冻结的质量绘图不启动模型计划；保留blocked业务状态。
- `/mcp barrier`关联原锁、原prepared/frozen日志、请求/目标/错误及当前发现schema。仅根级缺required参数且服务端逐项记录missing的普通写入，才构成人工候选。
- `/mcp resolve`不是恢复工具，不暴露给Agent。所有模式均要求显式用户确认原请求未执行、已结束且无运行/延迟操作。没有确认、活跃其他写入PID、真实未知超时、原生错误、截图、不一致或缺失证据均拒绝。
- 人工判断不是原生执行证明：记录`native_no_execution_proven:false`，旧unknown保持原样。以私有原始屏障归档、审计快照、hash及用户决定记录支持事后追溯。
- 用独占复核文件串行人工审定；批准后再次核对锁和日志hash，在归档前后检查源字节，避免静默覆盖新证据。失败不自动清理崩溃互斥锁。
- 丢弃当前连接、任务授权及文档绑定；不接管旧图、不自动继续任务、不重放。新请求只允许本连接新建工作图。
- 新写入/捕获屏障记录owner_pid，用于发现另一仍活跃写入者；旧无PID记录仍只能由用户人工核查。

## 影响与限制

该流程不是通用reset，也不替代Scheduler/Recovery已有权威对账。不支持凭远端错误文字自动声明无副作用。旧进程缺少PID或已不受Cader控制的延迟原生操作，程序无法证明不存在；这正是必须人工确认且默认拒绝的原因。原图内容和完整图纸质量仍须独立验收。

保留旧失败及ADR0011的不自动迁移策略；新增的是显式人工审定，不是启动自动迁移。原始证据只留私有目录，公开报告不提交私有图纸内容。
