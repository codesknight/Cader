# ADR 0013：依赖预检、部分执行与真实失败原因

日期：2026-11-21；状态：实施；关联REQ-032、BUG-027/028、[#20](https://github.com/codesknight/Cader/issues/20)。

用户请求HOUSE图层上的多段线，没有先创建图层。原MCP先AddPolyline、再设置Layer，发生“未找到主键”时已留下0层实体。单纯schema正确不能证明文档内的依赖存在。另一运行在规划时报QUOTA，却被质量待验证提示掩盖。

决定：

- Cader在已绑定的新工作图上，对显式图层依赖做实时程序查询；缺失/读失败一律在写请求派发前拒绝，不触发unknown冻结。返回纠错动作，由模型决定创建图层或改用已有图层，不隐藏执行写入。
- 批次仍串行，提交项、失败项和未派发项明确区分；不把批次包装为事务，不整批重放。
- MCP在Add*前校验图层存在/可写。属性设置失败仅尝试清理本次调用直接获得的新增实体引用；不全局Undo、不删除已有图形。清理失败保留原错误与清理错误；不声明权威回滚。
- 原生异常不凭文字自动改为“未执行”。COM失联、Add*已执行但未返回引用、响应丢失、截图未知等继续冻结；原Drawing2证据和残留不自动清理。缺参人工复核入口不扩展为通用reset。
- 规划与绘制模型调用均记录结果；模型失败在质量调度层阻断，未获得计划明确失败。CLI优先原错误码，冻结时展示首发错误，而非只显示质量未通过。
- 实机暴露的截图延迟采用前台PlotToFile，显式fit-to-page，验证布尔回执；以PlotConfiguration快照完整恢复而非只还原设备名，保留恢复失败。拒绝覆盖导出文件，不自动重打；原生未知仍保留屏障。依据与实机证据见验证报告。

反复屏障的根因是可避免的错误进入非原子写入，以及普通COM工具没有可关联的权威终态。此次修复前一类并增加局部失败清理；要覆盖进程崩溃和丢回执，仍需复用现有managed profile的原生事务、持久operation ID及终态对账，并补齐它尚不支持的几何能力。不能用“查到一个实体”证明某次请求完整成功，也不能因一次查询为空就自动重放。这些能力未在本轮伪装为完成。
