# REQ-051：渐进式绘图与局部源门禁

日期：2026-11-27（Asia/Shanghai）。关联 [Cader #20](https://github.com/codesknight/Cader/issues/20)、Milestone 3。需求来自用户的大图运行日志、用户提供的 Bug Triage 与 Progressive Drawing Skill v1.0 ZIP。附件是审计与实施参考；执行范围由用户本轮请求确定。原始设计附件不改写，原始运行日志留在私有目录。

## 证实与假设

- 用户失败 run 的 `quality.json` 实际记录 `SOURCE_COMPONENT_INVENTORY_FAILED`、空 checks 和未接受状态。原实现先通过整图源观察/器件/网/标签检查，再允许规划和 CAD 授权；后面的逐组件 Scheduler 无法解决前置整图阻塞。
- 源对象/标签 schema 各最多 32 项是代码事实，但不能据此断言所有失败都是数量超限。实际错误还包括源端子分组、位置/端子清点分歧、标注范围及模型响应格式。
- 本轮真实回归又证实了局部坐标越界、图框区域被误要求网表、有效 DAG 被要求按输入数组排序，以及共享锚点错误缺乏具体字段反馈。这些与 MCP 连接成功可同时发生。
- 权限锁死、COM 失连和某个后台只读分析函数未直接暴露，不是这次零写入的充分根因。未以重连、删除屏障或开放私有目录处理源观察失败。

## 实现边界

保留 DSH AgentLoop、Cordis、独立 AutoCAD-MCP 和 ExecutionSession。新增的是现有任务入口中的渐进 Scheduler，没有新 AgentLoop、领域硬编码、模拟 CAD 回执或新子 Agent 框架。

1. **Skill 与上下文**：显式 Catalog 注册 main/vision，只读；使用原 Loader 和 Available。大于等于 800 万像素的重绘参考、明确复杂/分阶段请求进入渐进调度，简单图形继续原短流程。纯分析先路由为 analysis，工具执行层不给写权限。入口 Skill、分解/验证/恢复资源按阶段加载并记录 `skill.loaded` 的 hash；目录元数据常驻不等于正文全部加载。
2. **范围合同**：模型提交完整覆盖请求范围的不重叠矩形区域、DAG 和共享锚点。程序查覆盖/重叠/重复 ID/循环/非法锚点，按 DAG 排序；参考区边界对齐原始像素，邻区共用同一全局 CAD 坐标。锚点错误返回具体 ID、位置、区域范围和下一步动作。
3. **局部门禁**：现有源观察、独立清点、连接和标签模块按区域复用。观察工具必须声明 BASE 裁片坐标；工具层检查声明并转换到原图坐标，主 Agent 获得程序转换的 CAD 布局。Schema/图像详情不再要求模型逐点手算整图偏移。图框/表格按实际局部类型处理；带端口的导线不能冒充器件。
4. **不确定项**：独立视觉分类保留原记录。本区必要事实阻止本区验收；跨区事实需要合法共享锚点并进入最终必验项；只有未请求的物理比例尺、源文件格式/实体编码能列为非本次条件。不能用此分类豁免图形、标签、颜色和连接保真。
5. **有界细分与待验稿**：未执行区域最多细分两层，总区域不超过 64；旧失败留在 decomposition history。仍无法完整清点时，只能由两次独立源像素观察共同确认的有限几何片段进入待验稿。新建操作必须符合这些已确认片段，遗漏内容不生成。路径用可独立读回的 AcDbLine 端点验证，不能用多段线 bbox 代替。此分支固定为 partial，`partial_verified` 永远不能满足整区覆盖、完整拓扑或整图完成。
6. **每批验证与修复**：整批预算和原始工具参数先检查，CAD 写串行。Patch 或单次有效写入后自动实际读回、查边界/重复/区域归属并视觉检查。图层外观修改也会使视觉缓存失效；不能只看几何 bbox 未变化。失败交回 Scheduler，不能让主 Agent 继续派发下一批。修复最多三轮，只能修改本区域且属于原任务写账本的实体；其他区域图层受保护。主 Agent 也可主动走统一视觉入口，同一有效区域结果复用。
7. **进度与恢复**：同一 task/source/scope/plan/connection/document、操作 ID、区域实体、批次结果及观察 hash 持久化。续跑核对全部绑定和新鲜读回；确认写入不重放，unknown 先对账。预算续轮与任务总上限分开，阶段不会自行重置预算；恢复保留累计 token/工具/CAD/模型步数及起始时间。持久化失败停止后续 CAD 派发并释放本任务授权。
8. **交付**：局部通过不是完成。全部区域、共享锚点、跨区未决条件、最终图像和实际读回都通过后才接受；需要 DWG 时复用原受控保存、文件指纹、独立只读重开及支持的摘要查询。MCP 的 partial summary 不冒充完整几何或语义验收。

## 用户可观察行为

CLI 显示当前区域、细分、实体数和批次验证状态。`/quality` 与动态任务上下文包含 failure、未通过条件、区域/批次与诊断，不再出现阻塞但空原因。`cader_quality_diagnostics` 只读本任务程序状态，不能读 `.cader` 任意文件。视觉报告 fail/uncertain 和区域未验不会显示为成功完成。

`max_model_steps` 保留普通运行的模型步数限制；质量任务新增独立 `max_task_model_steps`（默认 400），源观察、主 Agent 和视觉共享累计。原工具/CAD/token/时间/执行轮上限仍有效。读验证只在没有新 CAD 派发的验证边界续轮，不清空任务总预算；用户会话 `/compact`/跨聊天自动续接不是本次实现。

## 测试与证据分类

单元/DSH 模型夹具、真实模型、真实 CAD、完整大图必须分别报告。原始真实回归均用用户的 `img_001.png` 请求，未换成简单圆或旧 DWG 导入；失败日志保留。实际命令、最终状态及证据另见[真实回归报告](../validation/2026-11-27-progressive-drawing.md)。

Skill 来源为用户直接提供的 ZIP；只安装 SKILL.md 与三份 references 到 `configs/skills/progressive-drawing/`，并补充本仓库实际接口说明。INSTALL.md 和示例 Catalog 已阅读，未作为自动权限授予。AutoCAD-MCP 保持独立，本轮不修改相邻仓库。

## 实机驱动的补充修复

- 区域清单禁止 `saved_dwg`：局部验收发生在全图交付前，要求区域先保存会形成循环依赖。用户未要求实体实现方式时，不能增加任意 primitive 数量上限。保存与独立重开仍由原 P1 流程处理，不删掉交付验证。
- `new_drawing` 原生 ACK 和执行层读回确认后立即结束该阶段；不等第二次模型总结。解决“图已经新建，但模型第二步上限导致 Scheduler 当作未建”的真实失配。检查点也能核对本任务原 ACK，不能接管外部工作图。
- 确认创建请求的 schema 默认值和字段顺序规范化后做摘要；同一任务若原创建实体仍存在且未有已确认移动/删除等操作，原请求在 native dispatch 前拒绝，主 Agent 只能查询并继续缺失部分。这个防重放约束补充而不替代结构重复检测。
- Patch 部分失败时，已 ACK 前缀仍强制触发一次检查并交回 Scheduler，后续叶子不派发；零成功叶子不伪造批次。视觉/读回错误保留，不能让模型连续写入抵消未知结果。
- 真实密集裁片中，两次自由选择不同片段会得到零交集。第二次改为对同一组**不可信候选**做独立像素核查，允许纠错和拒绝，程序仍只准入双方几何一致的片段。未调整一致容差或伪造源真值；有效结果仍固定 partial。
- 显式同连接 resume 可对未通过/部分区域作最多三次有界源证据刷新；旧观察、待验稿、清单及失败归档在 `source_history`，已确认实体不丢失、不重建。新源证据若完整，重新建立区域清单并按实际现有实体补缺；缓存失败不是永久判决。次数和任务总预算不刷新。
- 恢复保存每个验证 scope 的源/视觉额度以及主动委派计数，防止 resume 绕过次数上限。图像采集/模型调用累计由旧证据与本轮统计相加，避免双计数。
- 用户取消时不再发起带已取消信号的保存，保留原取消/检查点原因；不会用“保存派发前取消”覆盖真正中断原因。仍有 unknown 的截图/写入禁止保存和自动恢复。
- 最终独立验收已通过时，历史中已被结果覆盖的模型阶段失败保留在轨迹，不再错误地使顶层 `report.ok` 为 false。未通过、取消、冻结或交付失败不享有这个分支。

当前原始大图并未通过完整自动验收。所有真实失败、阶段性 DWG、独立重开和恢复不变量见验证报告；这不是通过注册 Skill 宣称任意图纸重建成功。

分区执行次序由 `priority` 与原 DAG 共同决定，缺省50兼容已有检查点；高优先级仍须先完成真实依赖。细分继承优先级。实机证明原网格扫描在图框/索引上花费大量模型调用，新增内容优先调度使主体可先分析和绘制，完整范围仍必须最终通过，不能丢弃低优先级图框。跨区边界由实际导线连接证明；其他区域使用的图层按不区分大小写保护，避免同名别名改动已验外观。

新增真实回归驱动 `benchmark/run-progressive-case.mjs`：显式启用真实服务及CAD授权，必须新空工作区；生产Session/Task执行、首个通过检查点中断恢复、原生身份/单次新建/累计预算不变量及未验非零退出。脚本不含特定图形序列或源真值，CI不调用付费和本机CAD。
