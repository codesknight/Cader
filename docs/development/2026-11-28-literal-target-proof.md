# 微小源标注的目标证据与坐标保持

REQ-053 / BUG124 / [#20](https://github.com/codesknight/Cader/issues/20)。原始大图 attempt18 的一个未执行文字项进入 uncertain，其余清晰区域继续绘制，没有 CAD 冻结或 unknown。

## 已证实的两处问题

真实轨迹表明，宽源裁片的一次读数串入了相邻行；单目标原始裁片只有 **76×27** 像素。两次目标读取中，一次 clear，另一次明确以图太小、笔画不清为由 uncertain。原图局部像素和候选框均保留，未把这种状态描述为用户手稿本身不可读。

代码还存在一个独立反例：当生产 OCR 与两次宽图读取有分歧，但两个宽图读数彼此相同时，原实现不再执行紧目标复核。这不能排除两次同样的邻行串读。

## 实施

- 只要生产假设与独立观察有分歧，必须使用两次单目标真实裁片读数；宽图一致不能代替目标证据。仍最多处理8个目标，未进入有界目标队列的其余分歧项保持 uncertain，不静默通过。
- 微小 TARGET 可做1–8倍整数 nearest 显示放大，以接近512像素长边。上限、像素面积和变换均程序校验，原始源图不改写。源 hash 不变，view hash 更新，`view_to_source` 含准确逆缩放；这不是新增分辨率或生成式修复。[Sharp 官方 resize 文档](https://sharp.pixelplumbing.com/api-resize/)提供对应 nearest 插值能力。
- 同一原始像素目标的两次独立 clear 读数才可修正先前分歧，大小写/单位/数值标点不折叠。仅归一连续空白。
- `refreshUnexecutedSourceReadings` 校验冻结索引、源 hash、原目标裁片、两次不同 worker、文字和旋转一致，并只允许没有 Native/操作 ID 的未执行文字项更新为源 accepted。旧分歧进入历史，不能改写已执行图元，不能产生 CAD/视觉通过。源批次对旧 uncertain 重读复用同一校验器。

## 实际测试和边界

`pnpm typecheck`、`pnpm test` **446/446**、`pnpm smoke`通过。覆盖四种旋转与显示缩放组合的 PNG 尺寸及可逆边缘坐标、非法缩放、宽图重复错误、真实大小写冲突、有界队列第9项不可通过、源刷新拒绝已有 Native、源/crop/id/旋转或 worker 证据不匹配。新增 fixture 的 quad/完整索引类型初次不符已修正，原失败日志保留。

真实原始目标通过当前源观察代码复核：一次宽图＋两次不同真实 VisionAgent 的目标图，两个目标均 clear 且字面/旋转一致。76×27 被显示为532×189（7倍）；实际发送图像的 hash 与准备器输出相同，逆坐标系数为1/7。独立 OpenCV 比较每个输出像素与原裁片逐像素复制，全部完全相同，0新增源信息。此次同时改进了显示及取证条件，不能仅凭一次运行宣称所有模型不确定都由尺寸唯一造成。

真实组件没有 CAD 调用，也未改变活跃任务质量文件；源刷新只在副本上 dry-run 为 accepted，Native数仍0、quality仍false。私有证据 `.cader/runs/source-worklist-20261127/target-refinement18/` 的 `result.json`、`events.jsonl`、`proof.json`、`pixel-proof.json` 保留。原始内容不提交公开仓库。

attempt18 主驱动已加载旧 `a08439b`，尚不会自动执行本提交的新源读取分支。已核实的源证据待其受控暂停后由同一校验器导入原会话，保留原质量快照和导入回执；这不是热更新或视觉验收。后续须真实补绘、完整源窗口、整图和 DWG 独立验证。无法获得一致目标证据的情况仍需明确请求用户核对，不能投票或猜工程惯例。
