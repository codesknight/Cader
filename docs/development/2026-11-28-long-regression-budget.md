# 原始大图回归的显式时间预算

REQ-053 / [#20](https://github.com/codesknight/Cader/issues/20)。用户要求资金补足后继续原图整图验收；仍须满足实际模型、AutoCAD、完整源图和DWG验证，不能以提高额度代替质量修复。

## 产品配置

实际原始大图有3620个源项，批次原生查询、文字读取和独立高清复核耗时显著。原先配置校验最多接受4小时，限制了显式长任务配置。现在只把`max_task_duration_ms`的可配置上界改为24小时；默认仍30分钟，工具、CAD、token、步数和轮数上限不变。配置6小时为`21600000`。没有新增在线改预算CLI命令，也不自动为任务增加时长或token。

## 本次研发运行的特殊操作

attempt14启动时为4小时/20M报告token/10000 CAD/14000工具的显式测试预算。Native与验收代码为Cader `bb8e8e8` / MCP `619696d`，不是默认CLI预算。运行至原始起始时间后10323834毫秒，研发操作者根据用户继续完整验收的授权，将**这次测试**的总时限调整为6小时。

调整通过仅限自有Node驱动的本机调试接口，在`setVerificationScope`只读函数边界进行：先核对PID、入口、工作任务、Native目标、无冻结、无未确认操作；只修改本次runtime时间配置并按原始起始时间重新设置deadline。before/after对比证明起始时间、模型步数、累计budget计数和Native目标完全相同。0 CAD调用、无图纸/几何/验收结果修改，随后继续原任务，调试接口已关闭。

这是人工研发操作，**不是**Cader CLI在线扩额或跨进程恢复能力，也不证明原先4小时限制下可以完成本图。原始4小时启动记录保留；另存时间授权审计，不能把累计计数或已验证记录清零。原始图纸和历史unknown屏障不因此改变。

私有审计为`.cader/runs/source-worklist-20261127/attempt14-time-amendment.json`。前两次辅助脚本失败分别是无监听端口时的PowerShell退出状态、Windows Node调试发现URL格式；均未改变时间预算，原console保留。第三次满足完整守卫才应用调整。不能将调试入口当作生产恢复教程或绕过unknown屏障的方法。

## 已观察的验证成本

某批32个图元原生检查全正确，宽图仅3个可辨，其余29个待验。最多24个目标的补拍全部通过，剩5个保持待验；原报告和实际补拍均保留，不合成pass，也未移动正确几何。该现象说明批次可见性核对和尾项收敛仍有成本，不能把CAD连接正常等同于质量完成。

配置上界的离线测试和原始整图最终结果分别记录。整图尚未全部通过前，Issue20 / BUG106保持打开；完整测试不会用简单圆形或候选残差替代。

## 研发操作失败及后续保全

上述时间调整后，辅助脚本清理本机调试入口时，在调试求值上下文中执行动态import，触发`ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`，导致自有Node驱动退出。这是研发辅助操作引入的错误，不是AutoCAD-MCP或模型服务的故障；该次回归没有通过，不能因之前的计数或时间调整而算成功。后续禁止对运行中的回归做此类时限调整。

退出堆栈位于`afterBatch`的只读守卫，尚未调用下一次截图；最后执行审计为5实体的`quality_snapshot_targeted`只读查询。独立新鲜Native查询确认2647实体与已确认账本集合相同，逐项源坐标/宽度/OCS/文字检查2647/2647通过、0多余或无效项；再一次全量Native数据完全相同后，另存新待验稿557302字节，SHA256 `8db0852d0465f68287e0179386277e4addf41dfa68c7691a947cfd5f4b31a21b`。这是外部保全，不是P1交付或整图验收。原quality、旧进程锁、失败console和时间审计全部保留；原进程的连接已失效，不由新客户端接管。

新的独立原图回归将从启动时配置6小时，采用新的工作图和任务；不是旧图的自动续接，也不将旧已确认操作重放到旧图。原始图纸与未知屏障继续受保护。
