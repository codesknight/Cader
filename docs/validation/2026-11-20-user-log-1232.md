## 参数预检缺口及离线复现

MCP适配器原始ToolDefinition携带parameters，但执行体直接调用服务器；DSH原始工具不保证代为校验输入。[validateCadArguments](../../packages/profile/src/cad-arguments.ts)只检查已有height是否为正数，不检查缺失；[补丁](../../packages/dsh-adapter/src/live.ts)的arguments也是任意object。

用实际DSH注册一个无服务器的原始工具：schema要求text和height，execute只增加计数；调用时仅传text。实际输出：

```json
{"kind":"offline-raw-definition-schema-probe","server_called":false,"cad_called":false,"missing_required_height":true,"tool_body_invocations":1,"isError":false}
```

这证明“schema可见/已转发”不等于“进入执行体前已经校验”。现有组合补丁测试用了defineTool且参数均合法，只证明串行和首错停止，没有覆盖原始MCP定义缺必填项。因此此前63/63不能作为该边界已正确验证的证据。

## 修复顺序与验收建议（尚未实施）

1. **P0：完整schema执行前校验**。直接CAD调用和补丁都校验必填/类型/枚举/嵌套约束。补丁可在任何写入前预检全部操作；具体工具arguments schema也应呈现给模型。不能仅为此案例硬补height。
2. **P0：错误分型**。本地参数拒绝明确failed_before_dispatch，允许模型纠参；可信且结构化证明未执行的服务拒绝独立建模。超时/丢响应/真实未知继续冻结，不能简单匹配报错文字后一律解锁。
3. **P1：权威诊断与恢复状态**。同时给出本轮/累计计数、缓存范围/时效、首发错误和明确恢复资格。recover被拒应显示拒绝原因，不能暗示再试或重启即可成功。
4. **P1：终端去重**。已输出的回复不重打，只补程序状态；说明性查询完成与CAD写任务仍冻结应分别表达。

必须新增真实原始MCP定义的无height负向回归，并验证不派发/不冻结、合法纠参可执行、补丁预检范围、部分成功后首错停止及超时仍冻结。实机再验证创建文字后能进入自动质量阶段。当前日志不足以证明整张电路正确或错误，完整验收保持未通过。
